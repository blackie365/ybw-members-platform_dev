# Magazine Firestore Backup — pre store-consolidation

Snapshot taken 2026-08-27 before collapsing the two magazine data stores
(`magazine_reader_editions` + `magazine_issues/*/pages`) into a single
canonical store.

## Contents of this folder
- `magazine_issues.json` — every `magazine_issues/{issueId}` document
  (issue metadata + `storyLibrary[]`), with each issue's nested
  `pages/*` subcollection docs embedded under a `pages` key.
  10 issues, 105 nested page docs at time of backup.
- `magazine_reader_editions.json` — every `magazine_reader_editions/{id}`
  document (the published reader edition, including its `pages[]` array).
  3 editions at time of backup.

Generated by `scripts/backup-magazine-collections.js`.

## Companion managed export
A full Firestore managed export (collection-scoped to
`magazine_issues`, `magazine_reader_editions`, and `pages`) was also
taken via `gcloud firestore export` to:

```
gs://newmembersdirectory130325.firebasestorage.app/firestore-backups/magazine-consolidation-20260827-151831/
```

That export is the authoritative, Firestore-native backup — it can be
restored wholesale with `gcloud firestore import <path>` if the
migration needs to be rolled back. This JSON snapshot is a
human-readable/diffable companion for verifying migration correctness
(document counts, spot-checking content) without needing to restore
the managed export.
